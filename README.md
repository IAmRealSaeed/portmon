# portmon

داشبورد وب فارسی برای دیدن **مصرف ترافیک هر پورت** و **منابع سرور**، مخصوص سرورهای تانل/رله و هر سرور لینوکسی که چند سرویس روی پورت‌های مختلف دارد.

یک فایل پایتون است، فقط با کتابخانهٔ استاندارد، و جز `nft` و `python3` چیزی لازم ندارد. نه دیتابیس جدا، نه وب‌سرور جدا، نه pip.

> **English:** portmon is a single-file, stdlib-only Python dashboard (Persian UI) that counts traffic per TCP/UDP port
> with nftables, groups ports, and shows usage per day/hour plus live server resources. Install on Debian/Ubuntu with
> `curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/install.sh | sudo bash`.

## امکانات

- شمارش دانلود و آپلود هر پورت با nftables. قوانین فقط می‌شمارند و هیچ بسته‌ای را رد یا قبول نمی‌کنند.
- گروه‌بندی پورت‌ها؛ هر پورت می‌تواند در چند گروه باشد. مجموع «همهٔ پورت‌ها» هر پورت را یک بار حساب می‌کند.
- گزارش امروز، دیروز، ۷، ۳۰ و ۹۰ روز یا هر بازهٔ دلخواه، با تاریخ شمسی و نمودار روزانه یا ساعتی. بازهٔ دلخواه ساعت شروع و پایان هم دارد، مثلاً «۷ آبان ساعت ۲۲:۰۰ تا ۸ آبان ساعت ۰۳:۰۰». بازه‌های تا ۴۸ ساعت ساعت‌به‌ساعت نشان داده می‌شوند.
- سرعت لحظه‌ای هر پورت و هر گروه.
- **ورودی سرور**: هرچه کارت شبکهٔ سرور گرفته، روزانه و ساعتی. همان عددی است که دیتاسنترِ «فقط ورودی» حساب می‌کند، پس مستقیم با پنل دیتاسنتر مقایسه می‌شود.
- **هشدار پورت زیر نظر نبوده**: اگر پورتی کاربر دارد ولی زیر نظر نیست، مثلاً تونل تازه‌ای که اضافه نشده، بالای گزارش نشان داده می‌شود.
- منابع سرور: پردازنده، رم، سواپ، دیسک، شبکهٔ کارت اصلی، تعداد اتصال‌ها و conntrack، و پرمصرف‌ترین برنامه‌ها.
- ورود با رمز (هش PBKDF2)، HTTPS با گواهی خودامضا، و قفل موقت بعد از ۸ بار رمز اشتباه.
- نگهداری داده: ساعتی و روزانه برای همیشه (چند مگابایت در سال)، دقیقه‌ای ۳ روز، منابع سرور ۷ روز.

## پیش‌نیازها

- Debian 11 به بالا یا Ubuntu 20.04 به بالا (هر توزیعی با systemd، `nft` و `python3` به‌جز نصب‌کنندهٔ apt هم کار می‌کند)
- دسترسی root
- یک پورت آزاد برای داشبورد (پیش‌فرض `8800`)

## نصب

### روش ۱: یک دستور (سرور به GitHub دسترسی دارد)

```bash
curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/install.sh | sudo bash
```

نصب‌کننده رمز داشبورد را می‌پرسد. بعد آدرس `https://IP-سرور:8800` را باز کنید. چون گواهی خودامضاست، مرورگر یک بار هشدار می‌دهد که باید قبولش کنید.

برای نصب بدون سؤال، مثلاً در اسکریپت، رمز و پورت را با متغیر محیطی بدهید:

```bash
curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/install.sh | sudo PM_PASSWORD='رمز-قوی' PM_PORT=9443 bash
```

### روش ۲: از روی کلون

```bash
git clone https://github.com/IAmRealSaeed/portmon.git && cd portmon && sudo ./install.sh
```

### روش ۳: آفلاین (سرور به GitHub دسترسی ندارد)

فایل `install_portmon.sh` را از بخش [Releases](https://github.com/IAmRealSaeed/portmon/releases/latest) دانلود کنید. برنامه و فونت‌ها داخل همین فایل‌اند. فایل را به سرور منتقل کنید و اجرا کنید:

```bash
scp install_portmon.sh root@SERVER:/root/
```

```bash
sudo bash install_portmon.sh
```

اگر کد را تغییر دادید، همین فایل را خودتان با `python3 make_installer.py` بسازید. خروجی در `dist/install_portmon.sh` ذخیره می‌شود.

### تنظیمات نصب

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PM_PASSWORD` | می‌پرسد | رمز داشبورد، حداقل ۸ کاراکتر. موقع به‌روزرسانی خالی بگذارید تا رمز قبلی بماند. |
| `PM_PORT` | `8800` | پورت داشبورد |
| `PM_AUTOADD` | `1` | در نصب اول همهٔ پورت‌های TCP عمومی را که روی سرور گوش می‌دهند زیر نظر می‌گیرد، به‌جز ۲۲، ۵۳ و پورت داشبورد. `0` یعنی با لیست خالی شروع شود. |
| `PM_DOMAIN` | ندارد | یک دامنه یا ساب‌دامین که به همین سرور اشاره می‌کند. به‌جای گواهی خودامضا، گواهی واقعی Let's Encrypt می‌گیرد. بخش بعد را ببینید. |
| `PM_CF_TOKEN` | می‌پرسد | توکن API کلادفلر برای همان دامنه. دامنه از راه DNS تأیید می‌شود. |
| `PM_EMAIL` | ندارد | ایمیلی که Let's Encrypt دربارهٔ گواهی به آن خبر می‌دهد. |

> اگر فایروال (ufw، فایروال دیتاسنتر و غیره) دارید، پورت داشبورد را باز کنید. بهتر است فقط برای IP خودتان باز باشد.

### دامنه و گواهی واقعی

با گواهی خودامضا، مرورگر هر بار هشدار می‌دهد و کروم پیشنهاد ذخیرهٔ رمز را نمی‌دهد، چون کروم روی صفحه‌ای که گواهی‌اش خطا دارد رمز ذخیره نمی‌کند. با یک دامنه، گواهی واقعی و رایگان Let's Encrypt گرفته می‌شود و هر دو مشکل حل می‌شود.

۱. یک رکورد `A` برای ساب‌دامین بسازید، مثلاً `pm.example.com`، که به IP سرور اشاره کند. در کلادفلر ابر آن را خاکستری بگذارید (DNS only)، چون پراکسی کلادفلر پورت `8800` را عبور نمی‌دهد.

۲. در کلادفلر یک توکن API بسازید: My Profile ← API Tokens ← Create Token ← قالب «Edit zone DNS». در Zone Resources فقط همان دامنه را انتخاب کنید.

۳. نصب کنید یا دوباره نصب کنید. نصب‌کننده توکن را می‌پرسد:

```bash
curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/install.sh | sudo PM_DOMAIN=pm.example.com bash
```

بعد داشبورد روی `https://pm.example.com:8800` باز می‌شود و آخر خروجی نصب باید `certificate for pm.example.com: accepted` بیاید.

- دامنه از راه DNS تأیید می‌شود، پس لازم نیست Let's Encrypt از بیرون به سرور برسد. این برای سرورهای داخل ایران مهم است.
- certbot گواهی را خودش تمدید می‌کند و بعد از هر تمدید portmon را ری‌استارت می‌کند. توکن در `/etc/portmon/cloudflare.ini` با دسترسی ۶۰۰ می‌ماند، چون تمدید به آن نیاز دارد.
- اگر توکن را خالی بگذارید، دامنه روی پورت ۸۰ تأیید می‌شود. پورت ۸۰ باید آزاد باشد و از اینترنت در دسترس، هم الان و هم موقع هر تمدید.
- اگر گرفتن گواهی شکست بخورد، نصب ادامه پیدا می‌کند و داشبورد روی همان گواهی خودامضا می‌ماند. چند خط آخر خطای certbot هم نشان داده می‌شود.
- با گذاشتن `PM_DOMAIN`، شرایط [Let's Encrypt](https://letsencrypt.org/repository/) را می‌پذیرید.

## دستور `portmon`

بعد از نصب، روی سرور بزنید:

```bash
sudo portmon
```

منو بالا می‌آید. نشانی داشبورد، وضعیت سرویس و نوع گواهی را بالای منو نشان می‌دهد:

```
  1) Update portmon
  2) Get an SSL certificate for a domain
  3) Change the password
  4) Change the port
  5) Restart
  6) Status
  7) Logs
  8) Uninstall
  0) Exit
```

- **۱. به‌روزرسانی:** آخرین نسخه را از GitHub می‌گیرد. اگر سرور به GitHub نرسد، می‌گوید فایل آفلاین را از Releases بیاورید.
- **۲. گواهی SSL:** دامنه را می‌پرسد و بعد توکن کلادفلر را (بخش «دامنه و گواهی واقعی»). اینترنت لازم دارد ولی GitHub لازم نیست.
- **۴. تغییر پورت:** پورت تازه را در فایروال سرور خودتان باز کنید.
- **۸. حذف:** اول تأیید می‌گیرد. بعد می‌پرسد تنظیمات و آمار بماند یا نه. پیش‌فرض این است که بماند.

همه را بدون منو هم می‌شود زد: `portmon update`، `portmon ssl`، `portmon password`، `portmon port`، `portmon restart`، `portmon status`، `portmon log`، `portmon uninstall`.

## به‌روزرسانی

`portmon update`، یا همان دستور نصب را دوباره اجرا کنید. داده‌ها، گروه‌ها، تنظیمات، پورت و رمز می‌مانند. دامنه و گواهی‌اش هم می‌مانند و لازم نیست `PM_DOMAIN` را دوباره بدهید.

## حذف

`portmon uninstall`، یا:

```bash
curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/uninstall.sh | sudo bash
```

این دستور سرویس، جدول nftables، `/opt/portmon` و دستور `portmon` را پاک می‌کند، ولی تنظیمات و آمار را نگه می‌دارد. برای پاک کردن همه‌چیز، از جمله گواهی Let's Encrypt:

```bash
curl -fsSL https://raw.githubusercontent.com/IAmRealSaeed/portmon/main/uninstall.sh | sudo PM_PURGE=1 bash
```

## مدیریت

| کار | دستور |
|---|---|
| منو | `sudo portmon` |
| وضعیت سرویس | `portmon status` یا `systemctl status portmon` |
| لاگ‌ها | `portmon log` یا `journalctl -u portmon -f` |
| ری‌استارت | `portmon restart` |
| رمز جدید (اگر یادتان رفته) | `portmon password` |
| دیدن جدول شمارش | `nft list table inet portmon` |

رمز را از تب «تنظیمات» داشبورد هم می‌شود عوض کرد. افزودن و حذف پورت و ساختن گروه هم از همان‌جا انجام می‌شود.

## فایل‌ها روی سرور

| مسیر | محتوا |
|---|---|
| `/opt/portmon/` | برنامه و فونت‌ها |
| `/etc/portmon/config.json` | تنظیمات و هش رمز (دسترسی ۶۰۰) |
| `/etc/portmon/cert.pem`، `key.pem` | گواهی خودامضا (ده‌ساله) |
| `/etc/letsencrypt/live/<دامنه>/` | گواهی Let's Encrypt، اگر `PM_DOMAIN` داده شده باشد |
| `/etc/portmon/cloudflare.ini` | توکن کلادفلر برای تمدید گواهی (دسترسی ۶۰۰) |
| `/var/lib/portmon/portmon.db` | آمار (SQLite) |

کلیدهای `config.json`:

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `listen` | `0.0.0.0` | آدرس گوش دادن. با `127.0.0.1` داشبورد فقط از طریق تونل SSH باز می‌شود. |
| `port` | `8800` | پورت داشبورد |
| `interval` | `60` | فاصلهٔ نمونه‌برداری (ثانیه) |
| `utc_offset_minutes` | `210` | اختلاف ساعت محلی با UTC برای مرز روز و ساعت (۲۱۰ = تهران) |
| `title` | `مصرف پورت‌ها` | عنوان صفحه |
| `tls_cert`، `tls_key` | گواهی خودامضا | با `PM_DOMAIN` نصب‌کننده خودش گواهی Let's Encrypt را می‌گذارد. خالی یعنی HTTP. نصب دوباره این دو را از نو تعیین می‌کند. برای گواهی دیگری از `PM_DOMAIN` استفاده کنید. |
| `domain` | خالی | دامنه‌ای که گواهی برایش گرفته شده. نصب دوباره از روی همین گواهی را نگه می‌دارد. |

بعد از تغییر این فایل، `systemctl restart portmon` را اجرا کنید.

## شمارش چطور کار می‌کند

برای هر پورت P، بایت‌های اتصال‌هایی شمرده می‌شود که **مقصد اصلی‌شان** P است. ترافیک کاربر به سرور آپلود و ترافیک سرور به کاربر دانلود حساب می‌شود. شمارش با conntrack (`ct original proto-dst`) در زنجیره‌های input، output و forward انجام می‌شود. برای همین اتصال خروجی خود رله به سرور مقصد، حتی اگر از همان شمارهٔ پورت استفاده کند، شمرده نمی‌شود.

عددها بایت شبکه‌اند، یعنی سرآیند IP و TCP/UDP هم حساب می‌شود. برای همین معمولاً چند درصد از عددی که پنل VPN برای همان ترافیک نشان می‌دهد بیشترند.

جدول `inet portmon` جدا از قوانین فایروال شماست و چیزی را تغییر نمی‌دهد. اگر `nftables.service` فعال باشد و قوانین را از نو بارگذاری کند، portmon جدولش را در نمونه‌برداری بعدی دوباره می‌سازد.

### «مجموع» با پنل دیتاسنتر فرق دارد؛ «ورودی سرور» نه

«مجموع» ترافیک خود کاربرها روی پورت‌های زیر نظر است: دانلود به‌اضافهٔ آپلود. دیتاسنتر چیز دیگری می‌شمارد، معمولاً فقط بایت‌هایی که وارد کارت شبکه شده‌اند. روی سرور تونل این یعنی:

- آپلود کاربرها،
- به‌اضافهٔ دانلودشان که از تونل برمی‌گردد، با چند درصد سربار خود تونل،
- به‌اضافهٔ هر پورتی که زیر نظر نیست.

کارت «ورودی سرور» همین را از شمارندهٔ کارت شبکه (`/proc/net/dev`) برمی‌دارد و برای هر ساعت و روز نگه می‌دارد. ری‌استارت و به‌روزرسانی portmon بایتی را گم نمی‌کند، چون آخرین عدد شمارنده در دیتابیس می‌ماند. ریبوت سرور از صفر شروع می‌کند. در اولین اجرای این نسخه، هفت روز گذشته از نمونه‌های «منابع سرور» ساخته می‌شود. اگر بازه‌ای فقط بخشی‌اش ثبت شده باشد، کارت تاریخ شروع را کنارش می‌نویسد.

اگر فاصلهٔ «ورودی سرور» با «مجموع» ناگهان زیاد شد، اول هشدار پورت زیر نظر نبوده را ببینید.

### پورت زیر نظر نبوده

هر بار نمونه‌برداری، portmon نگاه می‌کند چه کسانی به پورت‌های باز سرور وصل‌اند (`ss`). پورتی که زیر نظر نیست و دست‌کم از ۳ آی‌پی متفاوت به آن وصل شده‌اند، تا ۲۴ ساعت بالای گزارش نشان داده می‌شود، با تعداد اتصال، تعداد آی‌پی و نام سرویس systemd آن.

- **شنودگاه تونل‌ها:** پورتی که سرور آن‌طرف تونل به آن وصل می‌شود فقط یک آی‌پی دارد و هشدار نمی‌گیرد. SSH هم هشدار نمی‌گیرد.
- **«زیر نظر بگیر»:** فرم افزودن پورت را با همان شماره پر می‌کند.
- **«نادیده بگیر»:** هشدار را خاموش می‌کند. از لیست «پورت‌های باز روی سرور» در تنظیمات دوباره روشن می‌شود.

## امنیت

- داشبورد را پشت فایروال نگه دارید، یا `listen` را `127.0.0.1` کنید و با `ssh -L 8800:127.0.0.1:8800 root@SERVER` باز کنید.
- رمز قوی بگذارید. نشست ورود ۱۴ روز اعتبار دارد.
- `config.json` هش رمز و کلید امضای نشست را دارد. آن را جایی منتشر نکنید.
